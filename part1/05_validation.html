05 Validation: choose the best model out of sample

Goal

Score candidate models on data they have not seen, and pick one.

Criteria (and why)

Metric Meaning Role
Negative log-likelihood (log score) on test data how much probability the model gave to what happened; penalises overconfidence primary
Poisson deviance generalised squared error for counts secondary
MAE of annual beach totals average miss in incidents per beach per year; easy to explain secondary
Predicted / actual total calibration: are we right in total? check
Severe only: top-10 beach capture share of actual severe incidents that fall in the 10 beaches we ranked highest (random = 12.5%) check
AIC / BIC in-sample fit, penalised for size tie-breaker only

Why time-based: the forecast is for the future, so we test on the future. Random splits leak (same beach, adjacent months).

One caveat for all scores here: the test rows use the actual visitors, weather and safety hours of the test year. In the real forecast (step 06) those inputs are assumed, so the real error will be larger. Step 06 checks how much larger.

2. Scoring functions

All four functions take the actual counts y and the predicted means mu for the 960 test rows.

# Log score: average negative log-probability the NB gave to each observed count.
# theta = Inf is the Poisson limit (used for the benchmark, which has no dispersion).
nll_nb <- function(y, mu, theta) {
  if (is.infinite(theta)) mean(-dpois(y, mu, log = TRUE))
  else mean(-dnbinom(y, mu = mu, size = theta, log = TRUE))
}

# Poisson deviance: 2 * sum of y*log(y/mu) - (y - mu); zero when mu = y everywhere
dev_pois <- function(y, mu) 2 * sum(ifelse(y == 0, 0, y * log(y / mu)) - (y - mu))

# Add up each beach's 12 months first, then average the absolute miss over the 80 beaches
mae_beach_year <- function(y, mu, beach) mean(abs(tapply(y, beach, sum) - tapply(mu, beach, sum)))

# Rank beaches by predicted total, take the 10 highest, share of actual incidents they hold
top10_capture <- function(y, mu, beach) {
  a <- tapply(y, beach, sum); p <- tapply(mu, beach, sum)
  sum(a[order(-p)[1:10]]) / sum(a)
}

score <- function(y, mu, theta, beach) c(
  nll = nll_nb(y, mu, theta), dev = dev_pois(y, mu), mae = mae_beach_year(y, mu, beach),
  ratio = sum(mu) / sum(y), top10 = top10_capture(y, mu, beach))

Why the log score is the main criterion: the forecast hands Task 2 a distribution of incidents, not just a point. The log score is the only metric here that checks the spread as well as the centre. A model that is right on average but far too sure of itself gets punished each time an unlikely count turns up.

3. Compare candidate models

Each candidate adds one block of predictors to the one before, so the table shows what each block buys out of sample. Two variants test the open questions from step 04:

  • v versions replace offset(log(visitors)) with log_visitors as a normal term, so the data choose the exponent (EDA slope about 0.9).
  • M6 replaces the five fixed beach traits with one dummy per beach (factor(beach_nm)). It learns each beach’s own level, including anything about the beach that we have not measured. The visitor mix (surfer_prop, tourist_ratio) changes month to month, so it stays.
  • S_small is the small severe model from step 04.

make_f <- function(y, s) as.formula(paste(
  y, "~", paste(s$rhs, collapse = " + "),
  if (isFALSE(s$offset)) "" else "+ offset(log(visitors))"))

# Fit every spec on `train` for response y, score on `test`, plus the "same as last year" benchmark
run_split <- function(train, test, y) {
  fits <- lapply(names(specs), function(nm) {
    m <- tryCatch(suppressWarnings(glm.nb(make_f(y, specs[[nm]]), data = train)),
                  error = function(e) NULL)
    if (is.null(m)) return(NULL)
    mu <- predict(m, test, type = "response")
    data.frame(model = nm, t(score(test[[y]], mu, m$theta, test$beach_nm)), AIC = AIC(m), BIC = BIC(m))
  })
  # benchmark: same beach, same month, last year; floored at 0.1 so a zero last year
  # does not give probability 0 to any incident this year
  ly <- pmax(test[[paste0(y, "_ly")]], 0.1)
  bench <- data.frame(model = "B0_lastyear", t(score(test[[y]], ly, Inf, test$beach_nm)), AIC = NA, BIC = NA)
  bind_rows(bench, fits)
}

How to read this:

  • Each block helps, in order. For every severity the log score falls as season, conditions, safety and traits are added, so none of the blocks from step 03 is dead weight out of sample.
  • “Same as last year” loses badly on the log score (about 3.1 vs 1.7 for all incidents). Last year’s count is a noisy guess for one beach-month. Its annual-total MAE is reasonable (about 10 incidents per beach) because the noise cancels when 12 months are added. It is useful as a sanity floor, not as a contender.
  • Mild (and so all incidents): beach fixed effects win clearly. Log score 1.670 vs 1.710, and the annual miss per beach halves (6.2 vs 12.6). The five measured traits do not capture everything that makes one beach busier with minor incidents than another. Fixed effects pick that up.
  • Close calls: fixed effects edge it in this year (0.513 vs 0.521).
  • Severe: fixed effects fail. The log score doubles (0.235 vs 0.109). Many beaches had no severe incident in nine years, so the model sets their rate to almost zero. When one then happens, the model had given it a probability close to zero, and the log score explodes. This is overfitting, and exactly what the log score is there to catch: MAE barely notices it (0.258 vs 0.256).
  • The v versions (free visitor exponent) are slightly better than the offset versions with traits, and identical with fixed effects. The gain is small (0.003 to 0.012).
  • Calibration. Models with traits overpredict mild incidents by about 10 to 15% in this year. Fixed effects are within 5%. Every model underpredicts severe (ratio about 0.74): 26 happened, about 19 were expected. Severe incidents are rare enough that one bad year moves this a lot, which is why we check other years next.
  • Top-10 capture for severe. Our full model puts 46% of severe incidents in its top 10 beaches (random would be 12.5%), so the ranking is informative even though the total is off.

One test year is one draw. Before choosing, check that the winners hold up across years.

5. Challenger: XGBoost

Does a flexible machine-learning model find something the GLMs miss? We run gradient-boosted trees (XGBoost) through the same five folds and score them against the model chosen for each severity.

How it works here.

  1. Start from visitors. Each beach-month starts at log(visitors), passed as base_margin. This is the offset again: the trees learn incidents per visitor, not raw counts.
  2. Add small trees. Each tree asks a few yes/no questions (e.g. “swell above 2.3 m and lifeguard hours below 400?”) and each end point (leaf) adds a number to the log rate. The prediction is visitors x exp(sum of all trees), so on the same log scale as the GLM.
  3. Each tree fixes the current errors. With the Poisson objective a leaf’s value is roughly the log of actual / predicted for the rows it holds, shrunk towards zero when they have few incidents, then scaled by the learning rate (0.03).
  4. Interactions come free. Trees 2 to 4 levels deep combine 2 to 4 inputs, so effects like “swell matters more at rocky beaches” are found without writing them in. The GLM only has them if we add them.
  5. Stop before overfitting. Inside each training window the last year is held out to choose tree depth, minimum leaf size and the number of trees (early stopping), then the model is refitted on the whole window. The test year is never seen.
  6. Add a spread. XGBoost only gives a mean. For the log score we fit a negative binomial theta to the held-out year’s predictions; where that estimate is unbounded we use Poisson.

Inputs are the same as the traits model, with month and marine health as numbers and lifeguard and drone hours unlogged (trees do not care about monotone transforms).

xgrid <- expand.grid(max_depth = c(2, 3, 4), min_child_weight = c(1, 10))

# Tune on the last training year, refit on all training years
fit_xgb <- function(train, y) {
  last <- max(train$fy)
  d_in <- dmat(filter(train, fy < last), y); val <- filter(train, fy == last); d_val <- dmat(val, y)
  res <- lapply(seq_len(nrow(xgrid)), function(i) {
    p <- list(objective = "count:poisson", eta = 0.03, max_depth = xgrid$max_depth[i],
              min_child_weight = xgrid$min_child_weight[i], subsample = 0.8, colsample_bytree = 0.8,
              eval_metric = "poisson-nloglik")
    m <- xgb.train(p, d_in, nrounds = 3000, evals = list(val = d_val), early_stopping_rounds = 100, verbose = 0)
    list(p = p, n = xgb.attr(m, "best_iteration") + 1, m = m,
         score = min(attributes(m)$evaluation_log$val_poisson_nloglik))
  })
  best  <- res[[which.min(sapply(res, `[[`, "score"))]]
  mu_v  <- predict(best$m, d_val, iterationrange = c(1, best$n))
  theta <- tryCatch(as.numeric(theta.ml(val[[y]], mu_v, limit = 100)), error = function(e) Inf)
  list(m = xgb.train(best$p, dmat(train, y), nrounds = best$n, verbose = 0), theta = theta)
}

What it says:

  • Mild: close to a tie. XGBoost is marginally ahead (1.605 vs 1.612, 4 folds to 1, annual miss 7.0 for both), a fifth of the gap that fixed effects opened over traits in section 4. The beach fixed effects already hold most of what the trees find.
  • Close calls: XGBoost wins every fold (0.515 vs 0.537) and cuts the annual miss per beach by about 18% (1.53 vs 1.88). The gain is seven times the gap that separated M5 and M5v in section 4, so the close-call GLM is missing real structure, most likely interactions or curved effects. It also overpredicts less (1.08 vs 1.14).
  • Severe: no clear winner. XGBoost’s log score is slightly lower (0.0854 vs 0.0878, 3 folds of 5, which is chance with about 20 events a year), but it overpredicts the total by 12% on average while the GLM is right (1.12 vs 1.00), and its annual miss per beach is larger.
  • This is not tilted towards XGBoost: the GLMs were chosen on these same five folds, XGBoost was tuned only inside each training window.

Verdict. Keep the GLMs. For severe, the GLM’s total is right on average, its range can be simulated from coef and vcov (step 06), and its effects are what Task 2 needs; XGBoost’s edge is within noise. For close calls, the XGBoost win is a signal, not a replacement: the next step is to find what it picked up (e.g. SHAP interaction values) and add those terms to the close-call GLM.

6. Decision

One model per severity, each a negative binomial GLM with offset(log(visitors)):

Severity Model Decided by Runner-up
Mild M6_beachFE: season, conditions, safety, visitor mix + one dummy per beach log score; a fixed-effects model won all 5 folds M6v tied (so take the simpler offset version), M5v 0.03 worse
Close call M5_traits: the step 04 model (season, conditions, safety, visitor mix, beach traits) mean log score over 5 folds M5v 0.003 better, not worth the extra term, so we take the simpler offset version
Severe M5_traits (same as close calls) mean log score, calibration 1.00 over 5 folds M5v tied; fixed effects overfit badly

Why this split makes sense: fixed effects need data. Mild incidents happen about 3,300 times a year, enough to learn each beach’s own level. Close calls and severe incidents are too rare for that, so they borrow strength across beaches through the measured traits (rips, rocks, fishing, rockpools, length). That is also the more useful model for Task 2, since it says why a beach is risky.

Forecast totals for all incidents are the sum of the three severity forecasts.

What to tell the panel:

  • The models were chosen on five years they had not seen, not on how well they fit the past.
  • For severe incidents the model gets the total right on average, but any single year can be off by about a quarter (FY2026: 26 actual vs about 19 predicted). Report a range, not a point (step 06).
  • The ranking of risky beaches is more reliable than the count: the top 10 beaches hold about 45% of severe incidents, against 12.5% at random.
